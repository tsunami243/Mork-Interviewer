# 面试出题质量人工验收

使用仓库的公开样本或合成项目叙述，不要把真实简历粘进公开测试记录。与旧 Planner 比较时，模型版本、材料和轮数应保持相同。

## 验收口径

每条问题分别按 0/1/2 分评估：**自然程度**（像项目面试官而非罗列术语）、**针对性**（参考项目材料及上一轮回答）、**单一性**（只问一件事）。首题应从项目职责或主流程切入；追问必须沿前一答深入，而不是随机换技术。每轮记录参考题 ID、问题、耗时与是否降级。10 个场景中至少 8 个达到三个维度均不低于 1 分，才认可题库质量。

| 场景 | 合成主张 | 首题或追问关注点 |
| --- | --- | --- |
| 1 | 饮食推荐采用四阶段管线 | 先请候选人讲本人负责的步骤 |
| 2 | 菜品候选由 RAG 召回 | 再追问召回结果如何影响业务决策 |
| 3 | SQL 过滤预算和忌口 | 询问数据过滤和模型生成的职责边界 |
| 4 | Redis SessionStore 管理历史 | 询问会话隔离的实际设计 |
| 5 | TTL 清理过期会话 | 在其回答之后追问用户体验 |
| 6 | 提示词与规则双层防幻觉 | 问为什么仍需要确定性校验 |
| 7 | Kafka 异步推送消息 | 询问为什么不直接同步调用下游 |
| 8 | 重试场景需要消费幂等 | 根据回答追问重复消费时的影响 |
| 9 | 接口做令牌桶限流 | 询问外部 API 超限时系统如何处理 |
| 10 | 使用监控和自动化测试 | 询问如何确认上线后确实可靠 |

特别记下以下失败：首题就追配置参数、一句话连续问三个问题、引用不存在的项目实现、换主题时重复先前题目、没有参考题却显示为“检索成功”。
