# 面试工作台与知识库边界

## 布局

- 左侧窄导航：会话、知识文件、来源资料。
- 左侧文件树：实际Vault中的概览、实体、概念、资料，以及参考题/综合等已有目录。显示真实文件标题与数量；没有文件的分类为空，不生成演示知识。
- 中央：面试对话与回答输入。新建面试保留已有LangGraph流程，本次运行可切换最近会话，暂不跨重启持久化。
- 右侧：知识文件Markdown与来源的只读预览。选择文件不推进问答、不改历史、不写入文件。

文件树与预览局部刷新，不重跑面试节点。只预览Vault内允许的Markdown路径，禁止路径越界；不加载外部图片或执行HTML。普通笔记可预览，但没有发布元数据不会默认加入索引。

## 两个不同入口

**新建面试**：打开面试弹窗，添加简历和项目材料。这些文件只用于本场面试，提取的文字发给面试LLM，不会写入Wiki或建库原件仓库。

**拓展现有知识库**：位于中央对话区上方，打开独立建库弹窗。

1. 添加明确用于知识库的资料：只在本机私有目录暂存原件，尚不解析、不调用LLM/Embedding、不创建建库任务。
2. 核对“本次资料”后点击“开始拓展”：只授权这一批选中的文件。
3. 系统自动解析、排队、分段分析、维护证据ID、生成多页知识、保守发布和更新索引。不会再让用户逐步选择内部操作，也不要求常规逐页人工审核。

未选中的暂存文件、普通面试附件、其他本地文件不自动进入建库流程。取消弹窗不授权；已明确启动的任务可在关闭弹窗后继续处理。

## 持久化与恢复

原件保存在 `data/private/wiki-ingest/uploads/`，任务和授权标记保存在私有SQLite。暂存不等于建库授权。后台只拾取已授权上传；服务重启不会把未授权暂存自动转换为任务。

升级时，旧版尚未完成的“上传即自动处理”资料暂停为暂存状态，避免悄悄继续收费；已经完成的知识保留。旧版只有解析文本而无原件的失败任务不自动收费重跑，可以重新添加原文件后明确启动。

错误最多自动重试三次任务处理。原件与检查点保留；模型服务SDK自身的HTTP重试与任务次数不是同一个概念。最终失败可通过拓展入口再次明确启动，而不是取消来源安全校验。

## 溯源和发布

第一阶段定位来源句，程序允许有限的格式归一，并回填实际原句和位置；第二阶段只引用提供的证据ID。未知ID或无法定位的内容不会通过语义猜测强行入库。

取消了常规人审，但保留结构、来源、路径和版本校验。自动页面标记 `review_status: automatic`；系统校验不是人工审核，也不证明上传资料本身正确。

已有页采用带来源的追加式补充，保留旧正文和标签；冲突保留双方观点，不自行裁决。读取到的旧页不完整时建立关联补充页，不截断原内容。整批写入仍有备份、事务与恢复机制，外部修改不被强行覆盖。

## Wiki和索引

Vault仍是Obsidian兼容Markdown：`concepts/`、`questions/`、`summaries/`、`synthesis/`及来源快照。文件树能浏览已有`entities/`，不代表本轮新增了实体提取或自动导入任意文件。

原文件是私有暂存，Wiki中的来源文本在授权发布后才生成。`index.md`、概览与操作记录在发布后更新。

发布后自动增量更新LanceDB，复用兼容的旧向量；索引失败不撤销已保存知识。改变模型/维度/端点不会混用向量。目前保留历史快照，尚无自动清理。

## 费用、隐私和验证

添加建库文件只本地暂存；点击“开始拓展”后会把解析文字、相关旧知识发给模型，并使用Embedding服务，可能产生费用。只上传有权使用且愿意发送给配置服务商的资料。浏览器移除选择不自动删除持久化原件。

私有原件/任务/新生成页默认忽略Git，但已跟踪的知识或目录文件仍可能出现diff，提交前需检查私人内容和资料许可。

离线回归：

```powershell
& "..\.venv\Scripts\python.exe" -m unittest discover -s tests -p "test_*.py" -v
```

核心模块：`wiki_browser.py`（安全文件树/预览）、`wiki_ui.py`（显式拓展弹窗）、`wiki_uploads.py`（暂存与授权）、`wiki_automatic.py`（已授权后台任务）、`wiki_evidence.py`（证据ID）、`wiki_intake.py`（编译）及`wiki_publish.py`（发布）。

A-RAG的Wiki采用率及Wiki参与评分仍是独立问题，不能用工作台或建库成功代替效果验证。图片/OCR、音视频、联网研究、自治事实纠错与Milvus均不在本轮范围。
