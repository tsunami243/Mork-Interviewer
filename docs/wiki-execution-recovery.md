# Wiki 局部恢复与执行记录

本次为现有Python/React架构内的增量实现，没有移植外部GPL代码，也没有重做面试流程。

## 流程

专用上传授权 → 解析/分段分析 → 候选资格检查 → 页面与关系规划 → 独立页面生成/校验 → 整批关系校验 → 事务发布 → 索引更新。

资料标题、面经问题清单等容器不作为实体；未具备原文身份依据的实体候选只保留在来源摘要。实体来源检查仍然存在，不为了凑齐类型放宽校验。

## 执行记录

`wiki_events`按任务、执行会话、阶段、页面记录调用起止、耗时、模型/服务域名、响应结构、校验错误与缓存复用。`wiki_checkpoints`在项目私有SQLite内保存可恢复的结构化响应。UI通过“查看执行记录与恢复预算”读取归属本浏览器的任务记录；不暴露完整原文、提示词或密钥。

过去任务缺少事件时，不能反推调用总数；恢复旧缓存会明确标注历史费用未知。响应不带用量时计入unknown_usage，不假称0 token。SDK隐藏重试在Wiki专用模型工厂关闭；运行时显式记录网络重试。

## 局部恢复与预算

核心任务发生业务校验错误后停止，等待明确恢复，不再自动从头尝试三轮。网络异常最多按配置尝试请求；规划/单页格式错误最多进行一次定点修复。成功响应和已校验页面在恢复时复用，失败页独立请求，异步任务全部收集后才统一决定发布；不发布半批内容。

默认预算为64次模型调用、100000个已报告token、600秒累计活动耗时、24页；并发3，请求最多2次。可通过环境配置新任务；已停止任务的预算只能由用户明确增加，已消费计数不清零。token限制按响应回传统计，存在并发回包与未知usage时不能当作绝对计费上限；调用/耗时止损仍有效。Embedding更新独立记录，不算LLM预算。

文件版本变动继续受乐观锁保护，旧缓存不能强行覆盖用户编辑。此版本仍对旧版legacy流程保留原重试兼容，不把旧数据自动迁移或重新收费。

## 连接

规划可携带关系类别、理由与证据；引用存在和有依据的语义关联分开标记。旧链接兼容为structural_only；共享来源证据可标evidence_supported，但这不等于自动证明任意业务命题。新页面元数据保留关系记录；复制文件补链仍需分析和写入两次确认，使用同一关系记录结构。

## 当前任务恢复

只有原件摘要校验、缓存内容/来源证据/旧页版本检查通过，才可使用已有完整生成缓存进行恢复。资料级错误节点归回来源摘要，其链接重定向；其余概念内容不重新生成。恢复缓存本身不调用LLM，发布后索引更新仍可能产生Embedding费用。
